# DoBao — คู่มือส่งมอบและทดลอง

เวอร์ชันนี้เชื่อมบริการจริงสำหรับทดสอบในเครื่อง ไม่ใช่ mock แต่ยังไม่ใช่การอนุมัติเปิดรับข้อมูลผู้ป่วยจริง ใช้ข้อมูลสมมติเท่านั้น ข้อมูลที่กดยืนยันจะถูกจัดเก็บจริง

## เริ่มใช้งาน

1. เปิดบริการ AI ของคุณบน Mac ที่ `127.0.0.1:8765`
2. ในโฟลเดอร์ `muge` ใช้ Node 22+ และรัน `npm run dev`
3. เปิด **http://localhost:3000** อย่าเปิดไฟล์ HTML โดยตรง
4. อ่านคำเตือนทดสอบ/ประกาศ แล้วกด Google Login ด้วยบัญชีของคุณ
5. ในหน้าบัญชี เลือกอนุญาตจัดเก็บสุขภาพ; AI เป็นตัวเลือกแยก ไม่ถูกเลือกให้ล่วงหน้า

Login ใช้ Supabase Auth (Google provider) และต้องรัน migration 008 ตาม [SUPABASE_LOGIN.md](SUPABASE_LOGIN.md) ถ้าหน้าบัญชีแจ้ง `DB-CONNECTION` ให้ตรวจ `SUPABASE_URL` ก่อน

## ทดลอง flow ด้วยข้อมูลสมมติ

หน้าหลักใช้ปุ่มลัด “บันทึกวันนี้” และ “คุยกับ Baobuddy” หน้าอาหาร/กิจกรรมเริ่มจาก Baobuddy ถาม “วันนี้กินอะไรมาบ้าง?” หรือ “วันนี้ได้ขยับร่างกายบ้างไหม?” พิมพ์เป็นประโยคแล้วตรวจสรุปก่อนยืนยัน ไม่บังคับปริมาณ/หน่วย ฟอร์มและปุ่มลัดอยู่ใน “บันทึกเอง” ปุ่มลัดเพียงเติมชื่อ ไม่บันทึกให้อัตโนมัติ กดเก็บชื่อเป็นปุ่มลัดหรือจัดการเพื่อลบได้

แตะรูปหรือชื่อบัญชีเพื่อเปิด **โปรไฟล์ของฉัน** เปลี่ยนชื่อ–นามสกุล ชื่อที่ใช้ในแอป รูป และธีมได้ ส่วนข้อมูลสุขภาพแยกบันทึกต่างหาก: โรคประจำตัว ยาประจำ การแพ้ ความพิการ/ข้อจำกัด ความชอบ และเป้าหมาย ข้อมูลไม่ทราบเว้นว่างได้ และ “ยังไม่ทราบการแพ้” ไม่เท่ากับ “ไม่มีประวัติแพ้” ระบบให้ตรวจรายการก่อนยืนยันทุกครั้ง

รูปจะถูกย่อเป็นภาพสี่เหลี่ยม 256px เก็บในแถวโปรไฟล์ภายใต้ RLS ไม่สร้าง URL รูปสาธารณะ เปลี่ยน/ลบรูปได้ ชื่อและรูปไม่ใส่ใน AI health profile ข้อมูลสุขภาพใช้ field ที่บริการ AI รองรับโดยตรง เปิด “ข้อมูลที่ Baobuddy ใช้” เพื่อตรวจข้อมูลจริงจากบริการ เมื่อแก้โปรไฟล์ต้องยืนยันก่อนให้ AI ใช้ข้อมูลใหม่

หน้าติดต่อทีมอยู่ในบัญชี/ประกาศ หรือ `#support` ส่งข้อความและอ่านคำตอบแยกตามบัญชีได้ ไม่ต้องเปิด AI หรือ health consent และลบข้อความของตัวเองได้ ต้องติดตั้ง SQL 007 ก่อนใช้งาน ดู [ขั้นตอนตอบข้อความของทีม](SUPPORT.md)

การบันทึกเองไม่เรียกโมเดลสร้างคำตอบ และใช้ได้แม้ปิด AI consent แต่ยังต้องเปิดบริการร่วมวัน เพราะเป็นที่เก็บต้นฉบับสุขภาพและตรวจรูปแบบข้อมูล ไม่ใช่โหมด offline

| ส่วน | สิ่งที่ทดลอง | ผลที่ควรได้ |
| --- | --- | --- |
| Dashboard | เพิ่มน้ำดื่ม/เพิ่มเป้าหมาย/ติ๊กสำเร็จ แล้วโหลดใหม่ | ค่าที่บันทึกยังอยู่ ไม่เพิ่มข้อมูลสุขภาพตัวอย่างเอง |
| อาหาร | กรอกอาหาร → ตรวจร่าง → ยืนยัน | รายการขึ้นในประวัติ; พลังงานไม่ทราบต้องไม่แสดงเป็น 0 |
| ออกกำลังกาย | กรอกกิจกรรมและเวลา → ตรวจ → ยืนยัน | แสดงตามเวลาที่กรอก ไม่สมมติเวลาสิ้นสุด |
| ยา | เพิ่มยาตามข้อมูลสมมติ/ตรวจรายการก่อนยืนยัน | ชื่อและสถานะตรงที่กรอก ไม่สร้างคำสั่งใช้ยาเอง |
| ติดตามสุขภาพ | เพิ่มค่าที่วัดและหน่วย → ยืนยัน → แก้ไข | ประวัติอัปเดต; กราฟไม่รวมค่าคนละหน่วย/บริบท |
| Baobuddy | ถามวิธีใช้งาน หรือให้ช่วยเตรียมบันทึก | คำตอบจาก API ของคุณ; ถ้าเสนอบันทึกต้องตรวจและยืนยันเอง |
| บัญชี | แก้ชื่อ/ถอน AI consent/ดาวน์โหลด JSON | ชื่อคงอยู่, AI ถูกปิด แต่ manual entry ยังใช้ได้ตาม health consent |
| โปรไฟล์ | เปลี่ยนรูป/สี กรอกการแพ้และข้อจำกัด → ตรวจ → ยืนยัน | โหลดใหม่ได้ข้อมูลเดิม; ไม่มีการแพ้เริ่มต้นที่ระบบเดาให้ |
| ปุ่มลัด | เพิ่มชื่อ ลบทุกปุ่ม แล้วโหลดใหม่ | ปุ่มลัดตรงกับที่เลือกเก็บ ไม่เปลี่ยนเป็นบันทึกสุขภาพเอง |
| ลบข้อมูล | ตรวจจำนวนก่อนยืนยัน แล้วโหลดใหม่ | ไม่แสดงว่าลบครบถ้า Supabase cleanup ยังไม่สำเร็จ |
| ออกจากระบบ | Logout แล้วเปิด Google อีกบัญชี | ไม่มีข้อมูลจากบัญชีเดิมค้างในหน้าจอ |

หลังการเชื่อมต่อขาด ถ้าเพิ่งกดยืนยัน ให้ตรวจประวัติก่อนลองซ้ำ เมื่อยังอยู่ในร่างเดิม ปุ่มลองซ้ำใช้ key เดิม การลบมีรายการติดตามบน server จึงเปิดเว็บใหม่แล้วกด “ตรวจและทำต่อ” ได้ ห้ามสร้างร่างซ้ำเพื่อคาดเดาผลเอง

หากตรวจผลคำขอลบเดิมไม่ได้ เช่นร่างหมดอายุและต้นฉบับเปลี่ยน ระบบจะหยุดให้ผู้ดูแลตรวจ ไม่อ้างว่าลบแล้ว และไม่ลบข้อมูลใหม่อัตโนมัติ

## ตรวจงาน

```sh
npm run check
npm run setup:check
```

`check` ทดสอบโค้ดและสร้าง static bundle ส่วน `setup:check` ตรวจเครือข่ายและ schema แบบอ่านอย่างเดียว ไม่พิสูจน์ Google Login, RLS ด้วย JWT จริง, หน้าจอจริง หรือความถูกต้องทางคลินิกของโมเดล ผลที่ทำแล้วอยู่ใน [TESTING.md](TESTING.md)

## ก่อนเผยแพร่

1. ตรวจชื่อผู้ควบคุมข้อมูล ช่องทางติดต่อ ระยะเวลาเก็บ และสถานที่/region ตามจริงในช่องที่เตรียมไว้ ตรวจประกาศโดยผู้รับผิดชอบ แล้วปิด local test mode
2. เตรียม private HTTPS gateway ไป Mac พร้อม server secrets ใน Vercel ไม่ส่ง JSON/key ลงแชตหรือฝั่ง browser
3. ทดสอบ Google Login จริงและแยกข้อมูลสองบัญชี ตรวจหน้าจอบนโทรศัพท์จริง
4. รัน `npm run release:check` แล้วทำ checklist ใน [DEPLOYMENT.md](DEPLOYMENT.md) ก่อน deploy

บัญชี Google/Supabase Auth, consent events และ metadata ติดตามการลบไม่ถูกลบด้วยปุ่มลบสุขภาพ ไฟล์ที่ดาวน์โหลดและ backups ต้องจัดการตามนโยบายแยก ยาที่บันทึกไม่ใช่ push notification และ Baobuddy ไม่ใช่แพทย์
